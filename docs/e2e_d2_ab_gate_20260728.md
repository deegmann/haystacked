### Mechanism-level finding (not a gate failure, but a genuine behavioral change worth flagging)

The mechanism did change, exactly as the D1/D1a provenance instrumentation was built to
detect: pre-fix, 4b's fabricated `_source` for these 3 fields echoed the **internal AP0
`hint`** text verbatim, including the leaked `"NULL RULE — READ FIRST:"` prose (the D2 bug).
Post-fix, 4b instead echoes the AP0 **`user_description`** field's illustrative example text
(`"…-20°C for cold storage"`, `"…35°C for production hall"`) as its fabricated source. Both
are hallucinations (neither string appears in the real document — confirmed via the
pdfplumber re-extraction above, which returned 0 temperature/humidity matches at all). Both
are caught identically by Layer 0 (`source_is_grounded`), landing on the same final null
value. This is a **pre-existing, D2-unrelated defect**: 4b is prone to fabricating a
plausible-looking source by copying user-facing example text from the field's own AP0
`user_description`, independent of which marker-matching regex Pass 4c's prompt builder
uses. Layer 0 continues to catch it in 100% of observed samples (7/7 today). Recorded here as
an observation for the backlog, not part of the D2 pass/fail verdict.

Also observed: `required_operating_humidity_max_pct` went from `produced_by=4b`/hallucinated
(pre-fix run 4, raw_value=85) to `produced_by=None` (no 4b attempt at all) in all 3 post-fix
runs — a favorable, not adverse, shift (fewer fabrication attempts on this field post-fix),
though N=1 pre-fix sample with provenance is too small to call this a trend.
